# Skyboxes and scene environment

A skybox is a **background only**: it does not illuminate objects, create reflections,
set exposure, or provide sunlight. Add and aim a directional light separately. The
background follows camera rotation but not camera position.

## Authoring a cubemap

1. Prepare a **single DDS cubemap** containing six equal, square faces, not a 2D
   texture or a cube array. Use the standard DirectX order **+X, -X, +Y, -Y, +Z,
   -Z**. The world is Y-up and the default forward direction is -Z. Orient the
   images for DirectX cubemap sampling, including their face rotations; a labeled
   test cube is useful for checking seams and orientation.
2. Choose a DDS format matching the stored values. For display-encoded color use
   an sRGB DDS format (for example DXGI `R8G8B8A8_UNORM_SRGB`); sampling decodes
   it to linear. For linear data, including HDR radiance, use a linear format such
   as `R16G16B16A16_FLOAT`. Do not label linear values as sRGB or vice versa.
   Convert HDR/EXR sources to a cubemap DDS with an external tool; they are not
   directly skybox sources. Include mipmaps in the DDS if desired: supplied mips
   are preserved, not generated by the engine.
3. Place the DDS in project content with its texture `.meta` sidecar. In the Content
   Browser choose **New > Skybox...**, select the DDS texture, and save the asset.
   Open the skybox asset in the Content Browser to edit its cubemap reference.
4. In the **Environment** dock select the Skybox asset, adjust yaw, brightness,
   tint and fallback, and save the scene. The dock displays yaw in degrees; scene
   JSON and C++ use radians. Positive yaw rotates the sky around world +Y.

Keep `.meta` files with their assets: UUIDs identify the texture and skybox through
moves and builds. The optional `path` is a diagnostic hint, not a substitute for the
UUID. See [scene and asset guide](scene-assets.md) for metadata and content paths.

## File formats

For example, `game/materials/example-sky.skybox.json` contains:

```json
{
  "version": 1,
  "cubemap": {
    "id": "9f1b0b13-bd18-45f4-b9d8-52360b1cd201",
    "path": "game/materials/example-sky.dds"
  }
}
```

`version` and `cubemap.id` are required; `cubemap.path` is optional. The UUID must
resolve to a DDS texture containing one cubemap. Unknown fields and unsupported
versions are rejected. A scene's optional root environment can be authored as:

```json
"environment": {
  "skybox": { "id": "9f1b0b13-bd18-45f4-b9d8-52360b1cd202", "path": "game/materials/example-sky.skybox.json" },
  "yawRadians": 0,
  "brightness": 1,
  "tint": [1, 1, 1],
  "fallbackColor": [0, 0, 0]
}
```

Each environment field is optional. Defaults are no skybox, zero yaw, brightness
1, white tint and **black** fallback; `skybox: null` clears the reference. Values
must be finite, and brightness, linear RGB tint and fallback components must be
nonnegative. Values above 1 are allowed for HDR. Tint and brightness multiply the
sampled sky; fallback is linear RGB used directly, without those multipliers.

## Loading and output

The scene requests its skybox asynchronously. With no skybox, while loading, or
if the asset, UUID, DDS, or cubemap shape fails, the renderer displays fallback.
Check asset errors/logs and correct the source or reference; a failed request is
not retried every frame. Changing the skybox reference, reloading the asset, or
explicitly rescanning the catalog can request it again. Catalog rescans also
resolve renamed skyboxes by UUID. A failed live reload retains an already ready skybox. Asset
loaded/failed events and `AssetSystem` state can be used for diagnostics.

In the normal final view the existing present pass applies Reinhard tone mapping,
`color / (1 + color)`, to the rendered result, including the background. Thus
brightness and HDR values affect the tone-mapped result rather than mapping 1:1
to display values. This describes the existing output path; skyboxes add no gamma
correction or independent exposure control. Debug views have different output.

## C++ scene settings

```cpp
#include <engine/scene/Scene.hpp>
#include <string>

// scene is an engine::Scene&, and skybox is an engine::AssetReference
// obtained from the asset catalog (UUID plus an optional path hint).
auto environment = scene.GetEnvironment();
environment.skybox = skybox;
environment.yawRadians = 0.5f;
environment.brightness = 1.0f;
environment.tint = {1.0f, 0.9f, 0.8f};
std::string error;
if (!scene.SetEnvironment(environment, error)) {
    // Report error to the caller; scene settings are unchanged on failure.
}
```

Validation checks the settings but does not resolve the UUID; successful setting
does not guarantee that asynchronous loading will succeed. Scene initialization
and environment changes request the referenced skybox automatically.

The repository's ExampleGame demonstrates this with an original generated
256×256 sRGB cubemap and full mip chain; see `example_game/README.md` for the
reproducible generator command.
