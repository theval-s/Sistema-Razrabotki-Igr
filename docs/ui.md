# Game UI authoring

Game UI uses RmlUi 6.3 RML and RCSS, controlled by ordinary engine Lua scripts.
The exact implemented Lua signatures, errors, schemas and lifetime rules are in
[the Lua UI facade](ui-lua-facade.md); see also [scripting](scripting.md).

## Example and startup

`example_game/scripts/ui/example_ui.lua` is an autoload named `ExampleUI`, with
script reference UUID `8fc69da8-42e6-4375-9020-83ae5ab0de01` and diagnostic
path `game/scripts/ui/example_ui.lua`. The standalone host registers it in its
`StartGame` autoload list. For the editor, create a project, copy `example_game/ui/`
to its `content/ui/` and `example_game/scripts/ui/` to `content/scripts/ui/`, then
add the script in **Project → Autoload** as `ExampleUI` and press F5 to Play.
The UI works over the editor's default scene; the standalone example's custom native
animation controllers are not required for this UI-only project.
The catalog needs the adjacent `.meta` files; do not duplicate their UUIDs.

P opens the modal pause/settings screen; use Resume to unpause. I opens the
inventory, where Add and Clear replace the bound list and Close dismisses it.
Use Tab/Shift+Tab for forward/backward navigation and Space for standard button
activation.
The player field and volume slider are demonstration settings, not persistent
game settings or an audio control. The HUD is passive and shows bound player,
health and simulation time. `badge.png` is generated by `generate_badge.py` and
has partially transparent orange edges for visual inspection.
The autoload requests a locked gameplay cursor in `OnStart`, including after loading
a saved game. Opening a menu releases mouse-look; closing it restores the lock.

In the editor Escape is reserved for releasing game input rather than opening
this menu; click the Play viewport to reacquire input. UI callbacks run while
paused, whereas gameplay `OnUpdate` does not, so a paused menu must provide a
callback such as Resume rather than relying on an `OnUpdate` key poll.

## Assets and styles

Top-level documents are cataloged `.rml` assets with UUID sidecars. Lua may
load a logical path such as `game/ui/hud.rml`, or an asset reference whose UUID
is authoritative (its path is a diagnostic hint, not a fallback). The engine and
game roots are resolved independently of the process working directory. Nested
stylesheet, template, image and font URLs resolve relative to their source, or
can start with `game/` or `engine/`; `..` must stay inside its root. The example
uses `engine/ui/base.rcss` and a relative `theme.rcss`. Switch the latter to
`theme-warm.rcss` in each document for the alternate palette.

The base stylesheet supplies panels, buttons, inputs, lists, tooltip text, and
range/scrollbar chrome. The example styles use `dp` units, gradients and hover
transitions. RCSS is RmlUi's CSS-like language, not browser CSS: use the
[RmlUi property index](https://mikke89.github.io/RmlUiDoc/pages/rcss/property_index.html)
and the documentation for version 6.3. Do not assume browser layout, JavaScript,
or arbitrary CSS properties are available. Example content uses positioned
panels, scrolling, borders and rounded corners; rendering effects and advanced
filters should be verified on the target renderer.

`engine/ui/fonts/DejaVuSans.ttf` is DejaVu Sans, with Latin and Cyrillic glyph
coverage, distributed under `engine/ui/fonts/LICENSE`. This copy comes from
matplotlib v3.10.0's `mpl-data/fonts/ttf/DejaVuSans.ttf`. The UI subsystem loads
it as the default fallback and registers cataloged font assets; add font sidecars
for project fonts and specify their family in RCSS. Coverage does not guarantee
complex shaping or right-to-left layout. Check the required fonts, input methods,
candidate placement and monitor-to-monitor DPI behavior on your target systems.

Build-tree asset targets copy `engine/ui`, game UI and scripts with sidecars;
the editor install component also includes `engine/ui`. A project opened in the
editor supplies its own game content. Keep the font license with deployments.

## Models, events and ownership

Create models in `OnStart` before loading dependent documents. `Set` copies and
dirties a top-level variable; `Get` returns a copy, so mutate a Lua table then
call `Set` again. Provide an explicit array schema when starting empty: `{}`
otherwise infers an object. Arrays must be dense and homogeneous; Lua indices
are 1-based, RML expression indices are 0-based. See the schema example in the
facade reference and `example_ui.lua` for a changing list.

Documents start hidden. `Show("hud")` is passive, `Show("interactive")` handles
UI interaction, and `Show("modal")` blocks gameplay input. Hide or close a modal
to release capture. A visible interactive document requests a visible pointer even
over pass-through areas; those areas still pass gameplay interaction through.
Gameplay can request `Normal`, `Hidden`, or `Locked` through
[`Input.SetCursorMode`](scripting.md#cursor-modes). Interactive UI temporarily
overrides hiding/locking and restores the request when dismissed; a passive HUD
does not affect it. Pausing simulation keeps the UI interactive, while Escape in
editor Play explicitly releases input.
Subscriptions are registered by element ID with `document:On`;
callbacks receive a copied event and can run while paused. Handles belong to their
creating script instance; autoload resources survive level transitions, and owner
destruction or session teardown releases them. `SetText` escapes text; only use
`SetInnerRml` for intentional markup.

## Preview and reload

Build and run the example, or use editor Play with the autoload configured above.
Inspect the HUD over the scene, open P and I, scroll and change the list, then
capture a screenshot with the host OS screenshot tool. Compare the same window
size and DPI when changing themes; inspect the badge edges and text against the
scene. Small viewport media rules keep panels inside the surface and permit
scrolling taller menus.

`document:Reload()` queues a reload; check engine logs for completion diagnostics.
On success document handles and ID subscriptions persist but old element handles
are invalid: reacquire elements. A failed replacement retains the working document.
Reloading is explicit, not file watching; reload does not reload Lua code or replace
the font atlas. Restart Play after changing scripts or fonts. Reload rolls back on
default parser warnings as well as errors. In Debug builds the host enables the RmlUi
debugger, initially hidden; F8 toggles it when text entry is not active. Non-Debug
builds disable it. There is no Lua debugger API.
